# Прах и Железо — правила разработки

Браузерный арена-рогалик-автошутер (формула Brotato) в оригинальном гримдарк-готик-сай-фай
сеттинге. Соло + кооп до 8 игроков. Docker :8150 (localhost-only), наружу —
**https://ash.sanyago.space** (nginx + Let's Encrypt).

Полное ТЗ — `prompt_ash_and_iron.md`. Правила стиля и реестр ассетов — `ASSETS.md`.
Этот файл — источник правды по архитектуре и ограничениям. `AGENTS.md` — симлинк сюда.

---

## 1. Правовая рамка (нарушение = блокирующий баг)

Сеттинг **вдохновлён** эстетикой гримдарк-сай-фай, но всё содержимое оригинальное.
**ЗАПРЕЩЕНО** в коде, конфиге, текстах, промптах генерации ассетов, метаданных,
именах файлов и коммит-сообщениях:

`Warhammer`, `40000`/`40 000`/`40k`, `Space Marine`, `Astartes`, `Imperium`, `Emperor`,
`Ork`, `Tyranid`, `Necron`, `Eldar`, `Adeptus`, `Mechanicus`, `Inquisition`/`Inquisitor`,
`bolter`, `chainsword`, `servo-skull`, `aquila`, `double-headed eagle`, `skull and cog`,
иконография конкретных орденов.

**РАЗРЕШЕНО**: жанровые архетипы — готическая архитектура, силовая броня, фанатичная
теократия, техно-жрецы, орда мутантов, био-рой, металлическая нежить, ржавчина, кадила,
свитки-печати, лампады, свечи, тяжёлые шрифты, охра/кровь/сталь.

Все названия — из §3 ТЗ или сочиняются в том же ключе. `tools/pxl.py` отклоняет промпт
с запрещённым словом до отправки в pixellab — этот фильтр не ослаблять.

## 2. Архитектура

**Симуляция живёт в браузере.** Сервер — не симулятор. Никаких серверных тиков на Python.

```
Хост (браузер)                 Сервер (Flask + SocketIO)          Клиенты (браузеры)
 sim 60 Hz, весь мир    ──20Hz─►  релей комнат: emit(room=code)  ──►  ввод 30 Hz
 приём ввода 30 Hz      ◄───────  без симуляции                  ◄──  интерполяция
 рассылка снапшотов               /api/*, SQLite, мета                рендер 60 Hz
```

- **Соло — это комната из одного игрока.** Транспорт абстрагирован (`net/transport.js`):
  `LocalTransport` (соло, вызовы напрямую) и `SocketTransport` (кооп). Один и тот же код
  симуляции. **Отдельного «одиночного режима» не существует** — две ветки кода разъедутся.
- **Кооп — host-authoritative.** Авторитет у браузера хоста, доверие внутри комнаты.
  Хост-миграции нет: отвал хоста завершает забег, результат сохраняется всем.
- `app.py` — auth (сессии, werkzeug-хэши), REST `/api/*`, socket-релей.
  `rooms.py` — реестр комнат в памяти. `meta.py` — реликвии, ачивки, валидация забегов.
  `db.py` — SQLite.
- `data/` (volume): `users.db`, `game_config.json` (живой конфиг), `secret_key`.

### Структура клиента (`static/js/`)

```
main.js          точка входа: конфиг, профиль, роутер экранов
engine/          loop rng pool grid input sprites render audio
net/             transport lobby host client protocol
sim/             run player stats weapon projectile enemy spawn pickup level shop economy
ui/              screens hud shop_ui levelup_ui meta_ui tooltip
```

## 3. Жёсткие правила

1. **Никакого хардкода** названий, чисел баланса, текстов и texture-id в коде.
   Всё — в `config/game_config.json`. Код оперирует ключами.
2. Репо-конфиг `config/game_config.json` — **сид первого запуска**; живой конфиг лежит
   в `data/game_config.json`. Любой патч контента накатывается **идемпотентным скриптом
   в `tools/patch_config_*.py` сразу в обе копии**.
3. Спрайт грузится лениво по texture-id: `static/textures/<textureId>.png`, файла нет →
   цветной прямоугольник. Добавить графику = положить PNG, код не трогать.
4. Все тексты интерфейса — в `config.i18n.ru` (+ `en`). В коде только ключи вида
   `ui.shop.reroll`.
5. Конфиг у всех участников комнаты обязан совпадать: хост шлёт `content_version`
   в лобби, при расхождении клиент перезагружает конфиг.
6. Auth обязателен: сокет без сессии отклоняется.
7. Весь рандом забега — из `engine/rng.js` (mulberry32) от сида, выданного сервером.
   **Никаких `Math.random()` в `sim/`.**
8. Реликвии начисляет **сервер по своей формуле**, а не по числу от клиента.

## 4. Производительность (бюджет, не нарушать)

Кадр 16.6 мс на машине хоста при 8 игроках, 450 врагах, 600 снарядах:
**симуляция ≤ 6 мс, рендер ≤ 6 мс, сеть ≤ 2 мс.**

- **Ноль аллокаций в горячем цикле**: сущности из пулов (`engine/pool.js`), `for` вместо
  `map/filter/forEach` в `sim/`, никаких временных объектов и замыканий на кадр.
- Коллизии — только через `engine/grid.js` (uniform spatial hash, ячейка
  `config.sim.grid_cell`). **Никаких O(N²).**
- Рендер: один canvas, `imageSmoothingEnabled=false`, целочисленный масштаб,
  никаких `shadowBlur`/`filter`.
- Лимиты из конфига, при переполнении — **деградация, а не лаг**:
  `max_enemies = min(450, 250 + 30*(N-1))`, `max_projectiles` 600, `max_pickups` 400
  (сверх лимита прах сливается в стопки ×5), `max_particles` 300.
- **Снаряды не синхронизируются покадрово**: шлётся событие спавна, клиент экстраполирует
  полёт сам; урон считает только хост.
- Снапшот — только сущности в `config.net.view_radius` конкретного клиента, максимум
  `net.max_entities_per_snapshot`. Позиции — int16, углы — uint8, HP — uint8-проценты,
  дельта к предыдущему снапшоту. Бюджет трафика ≤ 30 КБ/с на клиента.
- Дебаг-оверлей `F3`: fps, мс sim/render/net, число сущностей, КБ/с, пинг, роль.

Бенчмарк: `node tools/bench_sim.js` — гонять после любой правки движка.

## 5. Технологические ограничения

- **Vanilla ES-модули.** Никаких сборщиков, TypeScript, React, npm-зависимостей на фронте.
- Backend: только `flask`, `flask-socketio`, `simple-websocket`, `werkzeug`.
  Новые зависимости — по явному согласованию.
- Один процесс, один воркер (реестр комнат в памяти) — не масштабировать по процессам.

---

## 6. Чего не делать

Серверной симуляции на Python. Отдельного одиночного режима. Хост-миграции, публичного
матчмейкинга, PvP, зрителей, внутриигровых покупок. Покадровой синхронизации снарядов
и рассылки полного мира каждому клиенту. Хардкода названий, чисел баланса и texture-id.
Запирания метапрогрессией предметов и базовых механик (закрываются только фракции,
персонажи, оружие, арены и мелкие улучшения). Скачивания чужих спрайтов и звуков без
совместимой лицензии (только CC0/CC-BY с указанием авторства).

## 7. Процесс

- Код пишет **kimi code** по спекам из `specs/`; архитектуру, конфиг, баланс и ассеты
  ведёт Claude. Диффы kimi ревьюятся вручную, самоотчёт исполнителя приёмкой не является.
- Модель: `kimi-code/k3` на `engine/`, `sim/`, `net/`; дефолтная K2.7 — на UI, конфиги,
  патч-скрипты, тексты.
- Каждый этап (M0–M8 в ТЗ) заканчивается **рабочей игрой** и коммитом.

## 8. Тесты

```bash
.venv/bin/python -m pytest tests/py -q   # сервер: API, мета, реестр комнат, валидация забегов
node --test tests/js/*.test.js       # чистые формулы sim (без DOM): статы, XP, лавка, экономика
node tools/bench_sim.js                  # 450 врагов + 600 снарядов, sim ≤ 6 мс/тик
```

Сквозные проверки в браузере (нужен поднятый контейнер, playwright в `.venv`):
`tools/smoke.py` — забег, fps, ошибки консоли; `tools/pad_test.py` — навигация по меню
геймпадом (пад подменяется фейковым `navigator.getGamepads`); `tools/coop_test.py
--players 8 --latency 80` — восемь настоящих браузеров в одной комнате.

**Внимание**: в установленном здесь node (v24.18.0) `node --test <каталог>` не работает —
он пытается загрузить каталог как модуль и падает с `MODULE_NOT_FOUND`. Запускать только
глоб-формой `node --test tests/js/*.test.js`.

Зависимости бэкенда стоят в локальном `.venv` (в системный Python их не ставим — на машине
живут соседние проекты). Создать: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`.
В проде зависимости ставит Dockerfile, venv туда не попадает.
